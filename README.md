# Acute — public status dashboard

Source for the public status page:

**https://testplay-byte.github.io/DASHBOARD/**

The Acute product itself is developed in a private repository. This repo
contains only the dashboard site and its curated, public-safe `data.json` —
no product source code, no secrets, no internal details.

## Design

- Light, high-contrast theme (off-white background, near-black ink) with an
  orange accent `#FF6B2C` — rebuilt from owner feedback on the first, darker
  iteration.
- Sections: product hero + last-updated stamp, key numbers, three pillars,
  the plan (NOW + upcoming), quality metrics, milestone timeline,
  principles, tech stack.
- Responsive (mobile-first), semantic HTML, keyboard-accessible, and it
  respects `prefers-reduced-motion`. The page renders fully without
  JavaScript; the script only adds motion (count-up numbers, animated
  progress bars, reveal transitions, nav scrollspy).
- Dark mode: automatic from `prefers-color-scheme`, toggle in the header,
  persisted via localStorage.

## The usage page (`usage.html`)

A second page with detailed usage telemetry — every project, every session,
every tool call:

- **Overview** — projects, sessions, sub-agent runs, tool calls, model
  requests, tokens sent/received, estimated cost.
- **Activity** — sessions started per day (pure-CSS bars).
- **Tool usage** — the global tool-call leaderboard, with failure counts.
- **Models** — the model mix: calls, token flow, cost.
- **Projects & sessions** — one collapsible card per project (tool + model
  breakdown, stat tiles), collapsible session rows (status chip, model,
  duration, tokens, cost, tool calls), and sub-agent runs nested under the
  session that delegated them, each with its own full stats. Filter to
  "sub-agents only", or expand/collapse everything.
- Everything is server-rendered HTML (native `<details>` collapsibles work
  without JavaScript); `assets/usage.js` only adds the filter, bulk toggles
  and the auto-opened first project.

### Refreshing the usage data

`usage.json` (committed at the repo root) is the page's data source. It is
generated by the export script in the **Acute source repo** — never edited
by hand:

```bash
# in the ACUTE-CODE repo (reads the app's SQLite DB, writes a public-safe snapshot)
node scripts/export-usage.mjs --out /path/to/DASHBOARD/usage.json

# then in THIS repo
node build.mjs
git add usage.json usage.html index.html assets/
git commit -m "usage: refresh snapshot"
git push
```

The export is public-safe by construction: session/project ids are hashed,
titles are sanitized (trimmed to 80 chars; paths, emails, hosts and internal
ids scrubbed; secret-like patterns redacted wholesale), and **no message
content, tool arguments or file contents ever leave the database**. The
exporter runs its own denylist over the finished JSON before writing it,
and `build.mjs` scans `usage.json` (and every generated file) again with the
site's fail-closed denylist before anything is written. If `usage.json` is
absent, the usage page renders a friendly empty state with the export
command — the build never breaks.

## Repository layout

| path | purpose |
| --- | --- |
| `data.json` | **all index page content** — the single source of truth |
| `usage.json` | **usage page data** — generated by ACUTE-CODE's `scripts/export-usage.mjs`, committed so the page ships with data |
| `src/template.html` | index page template with `{{PLACEHOLDER}}` slots |
| `src/usage-template.html` | usage page template |
| `src/style.css` | shared stylesheet — tokens, cards, bars, theme (edit here, not in `assets/`) |
| `src/usage.css` | usage-page-specific styles, loaded after the shared sheet |
| `src/app.js` | progressive-enhancement script (shared: theme, count-up, scrollspy, reveal) |
| `src/usage.js` | usage-page enhancements (filter, expand/collapse all, auto-open) |
| `build.mjs` | zero-dependency build: data + templates → `index.html` + `usage.html` + `assets/` |
| `index.html` | generated output — served by GitHub Pages |
| `usage.html` | generated usage page — served by GitHub Pages |
| `assets/` | generated copies of the CSS/JS with cache-busted URLs |
| `.github/workflows/deploy.yml` | rebuilds the output on every push to `main` |

## Update flow

1. Edit `data.json` (keep it public-safe — see policy below). To refresh
   usage telemetry, regenerate `usage.json` (see above).
2. Rebuild and commit:

   ```bash
   node build.mjs
   git add -A
   git commit -m "status update"
   git push
   ```

   GitHub Pages serves the `main` branch root, so the pushed `index.html`
   and `usage.html` go live within a minute. A GitHub Actions workflow also
   rebuilds the output on every push to `main`, so editing `data.json` in
   the GitHub UI (or forgetting to run the build locally) still results in
   a fresh page.

## Local preview

```bash
node build.mjs
python3 -m http.server 8080   # then open http://localhost:8080
```

(Opening `index.html` directly also works — asset URLs are relative.)

## Content policy (binding)

This repo and its build output are **public**. Allowed content: product
name/tagline/version, pillar states and progress, milestone one-liners,
aggregate quality facts (test counts, license verdict), and generic tech
chips. Never add: source code, internal file paths, credentials or
token-like strings, private model identifiers, internal record ids, ports,
notification topics, or links to the private product repo.

`build.mjs` enforces this mechanically: every generated file is scanned
against a fail-closed denylist (token patterns, credential patterns,
internal-path patterns, token-in-URL, …) and the build aborts with a
non-zero exit code before anything is written if a match is found.
