02

Features

What shipped in the last rounds — the daily-driver capabilities that are live in the product right now.

The launch question (app or site, your choice every run)

live

Since round 56 the launcher asks how you want to work before launching: [1] the packaged desktop app (the window with the embedded browser and the bundled engine) or [2] the site (local servers plus your browser — the launcher opens the address automatically). Enter keeps your last choice, the answer is remembered as the next default, and the app/site commands skip the question. When the desktop engine does not report ready, the launcher shows the engine's log tail and asks what to do next — retry the app, use the site instead, or keep the app — so a dead engine is never a dead end. The launcher's self-update now re-runs itself immediately (new launcher logic drives the very session it arrives in), the engine-watch timeout prints the engine's last output instead of going silent, and the status report names the remembered launch preference plus the engine's last successful boot.

Embedded browser

live

A real Chromium browser inside the app: since round 50 every browser tab is a WebView2 child webview hosted in the main window — no proxy, no tickets, full CSS/JS, one shared profile so logins survive restarts — and since round 51 the desktop app itself installs in one click (the launcher downloads the CI-built NSIS installer, seeds the API keys into the Windows secure store, and launches it), so the native engine finally runs on the owner's machine with a visible engine badge and an automatic proxy fallback. The sidecar-proxy renderer remains the outside-the-shell fallback. Viewport presets 375→1920 + custom + zoom + rotate; the agent's browser_control tool shares the same state.

Right-sidebar tabs

live

File viewer · Browser · Terminal · Sub-agents — a browser-style tab strip with per-session state and bounds-safe popovers; the Sub-agents panel renders phase cards (task → activity → files → report) with a live timeline and a failed banner + retry.

Notifications, everywhere

live

Notification center with bell + unread badge, SSE stream, desktop notifications when hidden, and Web Push to a closed window via a service worker.

Sub-agent live streaming

live

Multi-turn delegation with per-child sessions, live forwarded tokens (raw thinking + text streamed as they generate), the full live todo checklist, a centered stats footer (time, tokens up/down, tok/s, model), retry-from-event-log recovery, atomic concurrency slots, and per-provider key pools.

Approvals engine v1

live

Layered policy (blocked → destructive → safelist → confirm), interactive Allow once / Always allow / Deny, 120s fail-closed timeout, compound-command guard.

Command palette ⌘K

live

Symbol-search and file-open via Ctrl/Cmd-K with grep options (case-sensitive, whole-word, file glob, max results).

Project indexing

live

Symbol index + index tool — 318 files / 2 384 symbols indexed in 124 ms on the demo battery; codebase summary injected into every turn.

Web tools

live

web_fetch (real fetch, HTML-to-text, caps) + web_search — currently knowledge-search backed; the real search backend is Decision 1.

Streaming chat

live

SSE text deltas + interleaved tool calls + thinking blocks + per-reply usage stats; turns complete in the background and notify when you're away. The composer carries permission modes, thinking levels, a provider→model flyout picker, and a context donut with main/sub-agent/combined session stats; the runtime guards against no-progress loops (nudge at 3 identical calls, honest stop at 5) and the prompt teaches understand-first, fewest-steps execution.

Background turns + stop

live

Client disconnects no longer abort the turn — it completes, persists, and pushes a notification; an explicit stop endpoint returns a distinct aborted outcome.

Checkpoint snapshots

live

Every write/edit/delete records before+after content; real unified diffs in the chat; 30-day retention. (The restore button arrives in Track 2.)

Per-project rules files

live

Rules files in the project folder are auto-loaded into every turn's system prompt — a genuine agent-rules analog, file-based for now.

Free-model catalog + fallback chain

live

46-entry typed catalog (18 free models; default glm-5.2:free) after the old default died upstream. A persisted Free-only/All filter is shared by Settings, the chat picker, and the sub-agent picker; requests on free models carry a provider-side fallback (primary + openrouter/free) verified live through a 429 storm.

Sub-agent provider settings (temporary)

live

A dedicated Settings tab (explicitly temporary): OpenRouter key slots isolated from the main key (pool slots 2–4) and a tool-capable, free-first sub-agent model override applied to every delegated child turn.

Failed-turn error cards + retry

live

Failed turns persist a turn.error event (survives reload) and surface a live error card — model, reason, timestamp, Retry and Copy-details. Abnormal stream disconnects are detected client-side; a deliberate stop is never an error.

Chat geometry engine

live

The chat panel fills its column at every width with a readable 1080px centered column and zero horizontal scrollbars from 700 to 2560px; the right sidebar yields smoothly below the 480px chat floor (the earlier cap regression removed).

Agent memory system

live

Persistent per-project memory: memory_save / memory_recall / memory_list tools, a digest auto-injected into every turn's prompt (proved live: a no-tools turn recalled a saved decision), and a right-sidebar Memory tab with kind chips and delete.

Real web search

live

web_search now queries the real web via DuckDuckGo (html + lite endpoints, ad/self-link filtering, uddg redirect unwrapping) with an honest MediaWiki fallback — live-verified in-turn with 8 real results.

Session search · fork · revert

live

Full-text search across session titles AND chat history (?q=), one-click fork (copies the whole event log to a new top-level session), and revert-to-message with a confirm dialog (truncates the event log and appends a marker).

Streaming terminal

live

The right-sidebar terminal streams stdout/stderr chunks live over SSE with heartbeats, a Stop button, exit-code footers (green/red), shrink-only timeout/output-cap overrides, and an automatic sync-route fallback.

Sub-agent keys auto-provisioned

live

The launcher reads three optional sub-agent pool keys from its local credentials file (auto-appends them if missing), distributes them to the OS secure stores, and injects pool slots 2/3/4 — the Sub-agents settings tab shows them with zero manual pasting.

Security round: audit P0-3/4/5 closed

live

Spawned children get an allowlist environment and never inherit the provider keys; auto-approved commands are contained to the project root (reading outside it now asks first); web fetches pass a host gate (default doc/source allowlist + per-project always-allow hosts, interactive approval) and search queries are secret-scrubbed before leaving the machine — each control live-verified through a real model turn.

Interactive terminal sessions

live

Persistent shells per project: a real PTY engine (node-pty, pure-Node pipe fallback), a Run | Shell mode toggle with command history, live streaming with backlog replay for late viewers, idle reaping and per-project caps — shells never inherit secrets and never outlive the app.

Packaging v2: the installable desktop app

live

The app version is single-sourced across all four manifests and gated in CI (0.51.0 today); a Keep-a-Changelog changelog spans 0.37→0.51. The release workflow now builds TWO artifacts on version tags: the CRLF-verified launcher kit, and — new in round 51 — a Windows NSIS installer (ACUTE-CODE_<v>_x64-setup.exe, per-user, no admin) bundling a pinned Node 24 runtime and the staged agent sidecar, proven bootable before shipping; the launcher installs it silently and seeds the owner's API keys into the Windows secure store.

Session manager reachable + mobile drawer

live

The VLM verification pass found the session search/fork screen had shipped unrouted — unreachable at any size — and that phones had no navigation drawer at all (69px of content at 375px). Both fixed: the screen is live with sidebar navigation, and below desktop widths the sidebar is an overlay drawer (351px of content, auto-closing).

Context compaction

live

Long sessions no longer silently drop their history: when the context window overflows, the model itself summarizes the over-budget part into a dense briefing (task, decisions, files, errors, open steps) that becomes part of the session — fork and revert keep working, the summary is reused until the next overflow, and a summarizer failure falls back to the old trim instead of failing the turn.

Relevance-ranked agent memory

live

Memory recall now scores results by multi-token relevance (content-match strength, kind, importance and recency) instead of plain substring order; the digest injected into every turn ranks durable decisions above casual notes; and re-saving a known fact refreshes the existing memory instead of duplicating it — verified live through real model turns.

One-click file restore from checkpoints

live

Every file-diff card now carries a Restore action (with confirmation) that reverts the file on disk to its pre-edit content — the restore backend existed since the first checkpoint system but had no UI caller for 21 rounds. A load-order race that could permanently hide the recorded snapshot on the first diff card was fixed along the way.

Browser cookies that survive restarts

live

The embedded browser keeps cookies in the project database (parsed per the cookie spec, replayed and refreshed on every redirect hop), so logged-in sessions survive an app restart. Cookie values never reach logs, tool output, or the agent; cookies from the user's own browser can't be smuggled through; jars are kept per project profile.

One provider API layer

live

All provider management — CRUD, API keys, key-pool slots, connection tests, per-provider model configs, the catalog — now lives in a single typed client layer every screen shares. The settings tab's private HTTP plumbing (a third parallel copy) and a dead legacy tab behind it were deleted in the same sweep. Disabling a provider genuinely stops its turns now: an honest 'enable it in Settings' refusal instead of quietly proceeding.

Key + model-scoped connection tests

live

The connection test can target the primary key or any key-pool slot, optionally with a concrete model — a real one-token probe with measured latency instead of a bare reachability ping. Failures are reported as the provider sees them: an empty slot says so, a wrong key reads 'User not found', a throttled free model reports 429. Adding a pool slot no longer silently overwrites an occupied slot when earlier slots have gaps.

One served model catalog

live

Every model picker — sub-agents, the agent form, the connection-test selector — now reads the backend's served catalog (46 models, free-first, tool and vision capability flags) instead of each screen keeping its own hand-copied list. New models appear everywhere at once; a deleted upstream model can no longer linger in one screen's stale copy. The agent form also lists custom providers and suggests known ids while still accepting free text.

Launcher ships zero key material

live

The launcher template is a clean paste zone: two required lines, three clearly-optional sub-agent slots, every value a placeholder — the live keys it had shipped since round 44 are gone, and the launcher never writes key values. Scrubbing the baked-in defaults exposed and fixed a three-round-old parser bug that had silently ignored the owner's own pool-key values; a raw-key-reading API route with zero callers was removed in the same round.

Sub-agents at near-main-agent parity

live

A sub-agent delegated from a live chat can now do what the main agent can: when it hits a needs-approval action (a non-read-only command, a web fetch outside the trusted hosts), it pauses and ASKS — the approval card appears in the parent chat labelled with the sub-agent's code and role, and the decision releases it. Every sub-agent carries a short code (like S23I) on the chat cards, the tab picker and its tab; the Delegated card lists each running child live and clicking one opens it; the sub-agent view is a real chat transcript — task, replies, tool calls with results, todo progress — with a per-second clock. Stopping the parent also stops its children; background retries still fail closed instead of hanging.

A real files explorer

live

The Files action in the working sidebar opens a two-pane explorer: the project tree on the left (folders expand, files open on click, per-type icons) and the file's contents on the right — markdown rendered, code with line numbers and syntax colors, breadcrumb path. A Search button keeps the command-palette flow reachable, the tree collapses for narrow widths, and loading and error states are honest with retry.

The modern always-on-top folder picker

live

Browsing for a project folder now opens the modern File-Explorer-style Windows picker — and it appears ON TOP of your windows instead of hiding behind them — both in the launcher/browser setup and in the desktop app. The old-style tree dialog remains only as a fallback if the modern one cannot load; both pickers fail honestly with an error line.

Background jobs — commands that outlive their tool call

live

When run_command launches something detached (Windows `start /B`, Unix `&`, nohup), the call returns immediately with a job id and polling instructions instead of hanging on a pipe-holding grandchild — the exact 10-minute stall the owner reported. job_status lists/inspects every tracked job with its live output tail and log-file tail; job_stop kills it (process tree, process group, or command-line match); a hard watchdog tree-kills any command whose shell never exits within the timeout. The Terminal panel gained a Background-jobs view with live status and a Stop button per job.

Sub-agents are stoppable and supervised

live

The Stop control now works on sub-agents exactly like the main agent — a Stop button on the sub-agent panel header aborts just that child, and the parent agent receives an honest 'sub-agent was stopped by the owner' report instead of a silent hang. While a child runs, a supervisor heartbeat streams what it is doing every 15 seconds (last activity, elapsed time, tool count, todo progress) into the panel, and a child with no activity for 5 minutes is auto-stopped and reported as stalled. Both thresholds are configurable in Settings.

The real in-app Usage screen

live

The Usage page inside the app (previously a placeholder) is now a full analytics view over the local ledger: overview stat cards, a token activity chart with a 7/14/30/90-day range selector, a tool leaderboard with failure counts, model cards with token and cost splits, and a projects-to-sessions drill-down with sub-agent runs nested under their parents and click-through to each conversation.

A plugin-based tool system

live

Every built-in tool group (filesystem, search, git, terminal, web, browser, memory, todo, delegation) is now a self-contained plugin module behind a registry — the tool catalog is computed from the real plugin declarations, so the app's tool list can never drift from the backend again. External tools ship as .mjs files dropped into ~/.acute/plugins (on by default) or the project's .acute/plugins (opt-in), with name rules, collision handling, and fail-soft loading.

Self-healing engine connection

live

Since round 53 the app and its engine can never silently disagree: a branded splash holds the whole UI until agent-core is actually up (no screen can fire requests at a stale endpoint), the shell reports the REAL startup error when something breaks, a one-click Restart-engine re-runs the full lifecycle without an app restart, a watchdog notices mid-session deaths within ~20s and reconnects with a full data re-fetch, and every lifecycle line is written to sidecar.log for support. Root cause of the first-installer 'Could not reach agent-core' report — an ephemeral port persisted across launches plus a one-shot handshake race — fixed at every layer and pinned by regression tests.

Self-repairing installs + in-app engine diagnostics

live

Since round 54 the launcher and the packaged app fix and explain themselves. The launcher verifies the install on DISK (app binary, pinned Node runtime, bundled engine) instead of trusting the Windows registry entry — which survives a manual folder deletion — so a deleted or half-written install is detected and REINSTALLED automatically, running copies are closed before upgrades so files are never replaced under a live app, and after launch the console watches the engine's own log and prints a plain 'engine is up — port' confirmation (or the failure log, right there). Inside the app, the engine's error channel is finally captured: its stderr is piped into the engine log, a failed start no longer leaves a zombie engine process holding the database (the real reason the restart button kept failing), cold boots retry three times before giving up, and the offline screen now shows the last log lines IN-APP with a one-click Copy-diagnostics button — any future failure explains itself on screen.

The engine-boot fix (EISDIR + the key namespace)

live

Since round 55 the packaged engine actually boots. Tauri's resource_dir() on Windows returns \?-prefixed verbatim paths, and the shell handed them to the bundled Node as the program, the script argument, AND the working directory — Node starts from a verbatim program path but its module resolver cannot handle a verbatim entry script, dying with 'EISDIR: lstat C:' before running one line of engine code. Every packaged session since the first build showed 'Can't reach agent-core' while dev mode (plain paths) never saw it. All child paths are now stripped to plain Win32 form. The same round unified the credential namespace: reads and writes use the launcher's cmdkey targets (ACUTE-CODE/provider/<id>) so the seeded keys are finally found, with the pre-R55 keyring form kept as a read fallback.

The engine-bundling fix (the 189-junction link farm)

live

Since round 57 the packaged engine's dependencies actually ship. The installer's bundled node_modules was staged by pnpm's default layout — a LINK FARM (measured: 189 symlinks on the build machine = 189 junctions after NSIS pack/extract) that Windows installers do not preserve — so the installed engine died with ERR_MODULE_NOT_FOUND before its first log line, while every Linux-side check passed (Linux keeps links; the owner's disk did not). The staged tree is now a classic npm-style tree of REAL directories (301.5 MB → 124.6 MB), a zero-links gate fails the build if any symlink or junction appears anywhere in the tree that will be packed, and the release build now BOOTS the real staged engine with the real pinned Node runtime on a Windows runner — same command line, same environment, same ACUTE_READY handshake the app waits for — before the installer is ever built. The gate caught its own first two script bugs the same day it shipped; a dead engine can never be packed again.

Frameless window + integrated title bar

live

Since round 58 the app looks like a full-fledged application, not a page in an OS frame: the native title bar (close/restore/minimize + app-name strip) is gone, replaced by a slim in-app bar — full-width drag region with double-click maximize, app identity at left, min/max/close at right, translucent over the shell's ambient background. The deep review — R42 audit

Five-agent audit fleet: four parallel domain audits (agent core & tools · autonomy & orchestration · workspace & project UX · platform & spec gaps) plus a synthesis pass producing the benchmark and roadmap. Every claim was verified against the actual source tree — file-and-line evidence, not doc claims.

Reviewed against the owner's vision

The review target, in the owner's words: a full-fledged system that works autonomously, supports different kinds of projects, is highly customized for different tasks, does research and file changes, has full-fledged automations, and can continue or revert sessions.

Acute composite score 1.9 / 5 vs a 4.7 / 5 frontier — the average of the best competitor per dimension below
The verdict

The three near-parity dimensions — sub-agent orchestration, background autonomy, approval design — are precisely the architecture's core bets, and they are validated. Every major deficit (automation 0/5, ecosystem 0/5, research 1/5) is additive work on a sound foundation, not re-architecture.

Project management

Research & web

partial

Terminal & processes

partial

Honest one-shot runner (60s, output caps, history recall) for the user; agent commands approval-gated. No PTY, no long-running processes, dev servers blocked.

Context management

partial

Memory & skills

Automation & scheduling

missing

No scheduler, triggers, or workflows. Research + blueprints complete; MVP scoped in Track 4.

Multi-agent teams

missing

Extension ecosystem (MCP)

missing

Packaging & releases

missing

Runs as a dev launcher + source tree. Desktop bundler disabled, no versioned installer, no changelog — the Rust shell compiles again (fixed in R43; CI green), so packaging is unblocked.

Broken or false today. These erode trust and two of them are security holes that must close before any autonomous work is built on top. All are small fixes — one dense round.

P0-1

Rust shell failed to compile — CI red for 4 straight rounds (FIXED in R43)

HIGH S

A Tauri API mismatch in the embedded-browser code broke the desktop shell build in R39; the last four CI runs all failed while this dashboard claimed green. R43 found TWO real API misuses (user_data_dir renamed data_directory in Tauri 2; on_navigation is a builder method), fixed both, and watched the runs to success via the API.

P0-2

Status reporting was false-green

HIGH S

The dashboard and internal status file hand-claimed CI success, 243 tests, and stale milestones while CI was red and 262 tests were green. This rebuild makes it honest; the durable fix is auto-syncing CI status from the GitHub API at build time. (Since R43 this dashboard bakes its CI status from the GitHub Actions API at build time.)

P0-3

Provider keys leak to child processes (FIXED in R45)

HIGH S

Approved commands inherit the full environment including provider API keys — any executed script or dependency can read them. Must be scrubbed before autonomy work. R45 closed it: every spawned child gets an ALLOWLIST environment (buildChildEnv at all six spawn sites) — a live child probe prints nulls for every secret-bearing variable.

P0-4

Auto-approved commands are not path-contained (FIXED in R45)

HIGH M

The read-only auto tier (list/cat/grep/find) can touch any file on the machine, and auto-run build tools execute arbitrary project scripts. File tools are contained; commands are not. R45 closed it: the auto tier is now contained to the project root — outside-root, home-relative, parent-escape, and other-drive paths demote the command to the ask tier (cat /etc/passwd asks now); explicit always-allow rules still win.

P0-5

Web tools bypass the approval engine (FIXED in R45)

HIGH S

web_fetch and web_search make ungated outbound calls with arbitrary URLs — an exfiltration channel for prompt-injected content. The spec requires every outbound call to be gated. R45 closed it: fetches and agent-driven navigation pass a host gate — a default documentation/source allowlist plus per-project always-allow host rules with the same interactive approval commands use; search stays friction-free but queries are secret-scrubbed first.

P0-6

The app database lives inside the source folder

HIGH S-M

Re-downloading or cleaning the app folder destroys all sessions and settings. Needs a data directory outside the tree, pre-migration backups, and full export/import.

P0-7

Binary files corrupt on checkpoint restore

HIGH S

Delete/write snapshots read files as text; restoring a deleted binary writes it back corrupted. Must fix before the revert UI ships on top of it.

P0-8

Dead navigation routes on the in-app dashboard

HIGH S

Start-a-session and recent-activity buttons lead to an unrouted screen (404 placeholder); project rows drop the session id; one dialog links to another dead route. First-run credibility.

P0-9

Rot bundle: shutdown route, workflow YAML, stale docs

MED S

The shell calls a shutdown endpoint that does not exist; a corrupted branch filter sits in both CI workflows; the canonical worklog stops at R37; the API truth doc under-reports ~20 live routes. (R43 refreshed the worklog and documented the browser/browser_control routes in the API truth doc.)

P1

High-impact — unlocks the stated vision

Directly unlock the owner's stated vision: continuing sessions, reverting, different kinds of projects, research, and the first steps toward autonomy.

P1-1

Revert UI — the endpoint exists with zero callers (FIXED in R46)

HIGH S

The owner's explicit 'revert to a previous session' ask: a restore endpoint was implemented and tested, but the frontend could only view diffs. R46 closed the UI half: every file-diff card carries a confirmed Restore action that reverts the file on disk (hidden for file creations, where the backend would delete the file); turn-level revert shipped in R44. The binary-safe restore dependency (P0-7) remains open.

P1-2

Failed main sessions are permanent dead ends

HIGH S-M

Retry exists for sub-agents but not for the primary conversation — a provider crash mid-turn bricks the session. Generalize the proven retry pattern; also serialize concurrent turns (a latent interleave bug).

P1-3

Session search + uncapped list

HIGH S

The sidebar caps at 8 sessions per project with a dead '+N more' link; there is no search. At 50+ sessions the product becomes unnavigable.

P1-4

Session fork — branch from any midpoint

MED S-M

The event log makes forking a single copy-query: duplicate a session up to event N and explore a variant without losing the original. The experimentation workflow the owner described.

P1-5

Session export / import + markdown

HIGH S-M

Zero backup or portability story today. JSON export of everything + per-session markdown transcripts.

P1-6

Memory system v1

HIGH M

The spec's primary success criterion — remembering context between sessions — is unimplemented (the policy field is dead). Per-project markdown memory, injected per policy, editable in settings.

P1-7

Auto-compaction for long sessions (FIXED in R46)

HIGH M

Trim-only context silently amputates the original task mid-run. R46 closed it the researched way: the over-budget head is summarized by the model into a dense briefing persisted as a session event (fork/revert inherit it, the summary is reused until the next overflow, round-2 compactions fold the old summary); a summarizer failure degrades to the old trim, so compaction never becomes a new failure mode.

P1-8

Project kinds + per-project settings

HIGH M

The 'different kinds of projects' vision: research/writing/data/coding kinds with per-kind suggestions, tool defaults, and rules templates; plus a settings dialog (rename, color, default agent/model, approval-rule management) — there is no update route today.

P1-9

Persona merge + agent picker

HIGH S

Agent system prompts are silently discarded in project sessions (replaced by the project prompt), so all five seeded agents are inert; the chat agent picker was removed with the old top bar and its store field is dead. Merge persona + environment prompts; restore the picker.

P1-10

Edit-reliability ladder

HIGH M

The #1 agentic friction: edits fail outright on imperfect matches with no did-you-mean. The aider recipe — exact → whitespace-normalized → elision, structured errors with closest-candidate hints, up to 3 reflection retries.

P1-11

Real web search

HIGH S-M

Research is bounded by Wikipedia. A pluggable search backend (Tavily / Brave / Exa) keyed like a provider, with the current engine as fallback. Needs the owner's API-key decision (Decision 1).

P1-12

Approval queue + remote approve

HIGH M

Today an unattended agent waits 120s then is denied — not autonomy-ready. A persistent pending-approvals center plus Approve/Deny action buttons on push notifications turns the existing plumbing into a remote control surface.

P1-13

Cost tracking + budgets

MED S-M

Recorded cost is always zero although the model pricing table exists; a runaway loop has no financial brake. Wire the estimate and add USD caps per run/day.

P1-14

Scheduler MVP (cron)

HIGH M-L

The automation pillar's first real code: workflows + schedules tables, one sidecar loop, missed-run policy, manual-run-first. The n8n-pattern blueprint is already written and pre-audited for traps.

P1-15

Auto-team run mode

HIGH M-L

The flagship multi-agent ask: a cheap orchestrator model planning and delegating to a powerful worker. Types exist; session creation rejects the mode. Needs approval queue + budgets first (P1-12/13).

Important next — depth and the long game

Important for depth and the long game — MCP, vision, packaging, and the polish debt the audits catalogued.

P2-1

MCP client

HIGH M-L

The industry-standard extension mechanism — every competitor supports it. Turns any MCP server into a tool; the biggest ecosystem unlock. After approval tiers extend to external tools.

P2-2

PTY terminal

HIGH M

Long-running processes, dev servers, cd persistence, streamed output — an agent that builds but cannot run or verify its app is not autonomous.

P2-3

In-app file editing + diff review

HIGH M

The file viewer is read-only today. Edit mode with snapshot-first saving keeps checkpoints consistent; open-at-line from chat and the palette.

P2-4

Worktree isolation for parallel sub-agents

MED M

Five parallel agents mutate the same tree — last writer wins. Git worktrees per coding child with a user-approved promotion step.

P2-5

Per-role sub-agent tool limits

MED S-M

Children currently get the full toolset minus delegation; a researcher can write files. Role-level allowlists are one settings layer.

P2-6

Vision / image input

MED M

The vision-model field has existed since the first migration and nothing consumes it. Composer attachments → vision model; unlocks screenshot-driven UI verification later.

P2-7

Agent-driven browser automation

MED M-L

The embedded browser is user-facing only. Navigate/click/type/screenshot tools feeding the vision model close the research loop.

P2-8

WebSocket event bus

MED M

Two ad-hoc SSE channels today; the designed auth-framed gateway would unify streaming and unlock live automation UI. Design is already an approved ADR.

P2-9

Packaging & versioning

HIGH M

Bundling is disabled, no installer, no changelog, no version discipline. Path: fix the Rust build → CI artifact (portable zip) → semver + changelog → launcher consumes releases. Depends on P0-1.

P2-10

Configurable denylist + approvals audit viewer

MED S-M

The command denylist is hardcoded in source and always-allow rules are written but unmanageable. Two settings screens backed by existing storage.

P2-11

Skills system

MED M-L

SKILL.md folders with progressive disclosure — the universal standard per the research corpus; the agent form already has a skills field that does nothing.

P2-12

Repo-map context economy

MED L

Token-budgeted tree-sitter repo maps (the aider approach) are the long-term answer to multi-file awareness beyond the symbol index.

P2-13

QA & polish debt

MED M

Zero Rust tests; the SSE stream route has no unit tests; palette lacks keyboard navigation; unreachable legacy layout code; one prompt rule suppresses parallel tool calls the SDK supports.
